# Native structured clipboard acceptance — October 1, 2026

The native clipboard writes editable-element JSON as `io.zubair.sugarmaple.elements` and identical UTF-8 plain text on a single pasteboard item. Name/code copies stay plain text. Reads prefer the structured representation and fall back to text when the type is absent. Version-one and version-two transport envelopes are accepted; the editor still validates the complete dependency closure before making one paste transaction.

The custom UTI is declared as public JSON in the actual built app without adding a document-opening association. Invalid/future/Boolean/fractional versions, wrong markers, invalid UTF-8 and oversized transport payloads reject explicitly. Writes validate before clearing; a rejected invalid write preserves the previous pasteboard contents. The transport limit is 32 MiB and does not raise the smaller editable-node/image limits. AppKit write failures return an error instead of reporting successful copy.

Validation: the actual compiled Swift helper uses a unique named NSPasteboard, checks custom/text representations, structured precedence, Unicode, legacy text/version-one exchange, invalid reads and pre-write rejection preservation. It does not access the user's general clipboard. The fixture also checks the built Info.plist declaration and absence of a file association. The browser fixture uses stubbed native I/O and actual editor UI to copy hierarchy with Unicode text, distinguish name/code formats, paste through the bridge with remapped IDs and undo the whole paste. Typecheck, macOS build and the complete native acceptance command passed (including persistence, native access/MCP/stdio, compiled SwiftUI consumers and actual isolated WKWebView preview/repeated assets). The first real pasteboard check caught an invalid UTI spelling, corrected before acceptance.

This is a candidate slice of #18. Native/browser cross-app exchange with permission-denied/manual fallback, sanitized external HTML/Tailwind import and broader assets tests remain open. This does not close #18 or claim those flows are delivered. Review, merge and resulting main CI remain delivery gates.
