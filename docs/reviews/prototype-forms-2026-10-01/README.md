# Typed forms and overlay preview — October 1, 2026

Issue #47 adds authored text/password/email properties, initial values, accessible labels and disabled state across commands, the inspector, Canvas, DOM and portable code. Preview values live in a component-scoped runtime instead of the document. Navigate, Back, open/close overlays and Reset use stable targets. Escape, focus trapping/restoration, reduced motion and removed destinations have defined behavior. The Mac button launcher is focused explicitly because mouse clicks need not focus buttons on macOS.

The candidate passes 47 model tests/287 assertions, all 17 browser/consumer suites, typecheck, the offline macOS build, four native filesystem/socket fixtures, stdio unavailable-host behavior and actual Angular/Tailwind/SwiftUI consuming compilers. The SwiftUI fixture includes two IDs that would collide under punctuation replacement; generated state identifiers remain unique.

The actual QA WKWebView on isolated port48487 was edited through native input. Email/password changes survived navigation/Back; Reset restored authored defaults. AX showed a secure masked field and disabled input. Overlay open focused Close; Shift-Tab wrapped to Done; Escape and the authored Done action restored Open terms. MCP deleted an open overlay; it closed, reported the removal and restored its launcher. A missing destination produced a diagnostic. Preview Escape restored the original launch button. MCP deep comparisons before/after confirmed the checkpoint and undo journal were unchanged, including a Cmd+Z while preview was active. Automated and manual checks are distinguished in [verification.json](verification.json).

Reproduce automated checks with `bun test src/web/tests`, `bun run --cwd src/web typecheck`, `bun run test:e2e`, `bun run build:mac` and `bun tools/native-acceptance.ts`. For the live native fixture, copy the built Debug app into `build/prototype-qa`, assign a separate bundle ID and DEBUG Info.plist `SugarMapleTestSupport`/`SugarMapleTestPort`48487, then ad-hoc sign the copy. Start that copy, set `SUGAR_MAPLE_SUPPORT_DIR` to its absolute `build/prototype-qa/profile` and `SUGAR_MAPLE_MCP_PORT=48487`, and run `bun tools/native-prototype-test.ts --setup`. Perform native preview interactions and run the harness without flags to compare its saved authored baseline; `--remove-overlay` tests removal while open and `--capture` saves a revision-bound native snapshot. The harness rejects other profiles/ports. Original user documents are never used for QA.

## Supported limits

See verification.json. This does not close the separate native-window work in #14, the production component registry in #12, or richer state machines in #24. Web exports contain semantic controls and action metadata; SwiftUI consumers own the Button callback and overall navigation. Initial values are persisted mock data, not a password vault. Preview edits are not saved.
