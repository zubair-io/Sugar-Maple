# Authored scene projection — work toward #88

The props-only experiment uses intrinsic package layout. Protocol 2 adds a bounded, read-only scene feed to the same trusted Web Awesome consumer. It is partial implementation toward #88; native scene rendering, editor diagnostics, final comparison/review/CI and main integration remain incomplete. The production-integration NO-GO and arbitrary-source restrictions still apply.

`projectLibraryScene(document, settledRootItem, sourceRevision)` uses the authoritative scene and its settled model layout, not rendered DOM semantics. It preserves resolved parent-relative boxes from free/stack/grid/fill/hug/percent layouts, nested rotation, parent IDs, Default/header/footer slot names, resolved solid styles, pinned variants, local semantic overrides and bound source tokens. The result includes the document/root identity and source revision. A source/layout mismatch, missing bound token, gradient, unsupported font/kind, altered mapping or unsupported size fails explicitly before a feed is sent. The experiment supports only the exact trusted Web Awesome 3.14.0 mapping and ordinary frame/text/button/input nodes; it never evaluates a manifest's modules.

The strict packet has no document commands, filesystem paths, module URLs or executable source. Limits remain 256 KB per packet, 100 visible nodes, a 1,600 × 2,000 viewport, bounded coordinates, strings and styles. The root is an unrotated frame; rotated external ancestors are rejected. Duplicate IDs, broken/cyclic order, children beneath controls, unknown slots, mismatched semantic props and privileged keys are rejected. The existing iframe session, monotonically increasing transport revision, supersession, opt-in trust, stop/cancellation and capability restrictions remain. Authored source revisions cannot move backwards within a document.

`WebPreview.renderScene(scene, reset)` sends the immutable projection to actual pinned `wa-card`, `wa-input` and `wa-button` controls. Their host geometry uses resolved scene boxes. Card slot wrappers remove intrinsic padding and use the authored border to avoid shifting children. Source Card paint is applied directly; actual Button Default/Primary package appearance remains distinct from semantic fallback paint, with explicit fill/color/radius overrides reaching the actual shadow base. Pinned brand token bindings reach the real Primary appearance. This is a declared supported projection, not a claim that package default glyphs, focus effects or colors equal Canvas paint.

Inputs keep ephemeral values and focus across unrelated source updates and undo. An authored initial-value change or explicit reset replaces that local value; changing documents or removing a node discards its ephemeral state. Narrow node-ID action/change events are accepted only for the current enabled control kind, session and rendered revision. Neither the scene nor these events provide an authoring dispatcher in the preview.

Run `bun tools/library-preview-acceptance.ts` after explicitly installing/checking the pinned consumer cache. The gate covers strict contracts/typecheck, legacy real-package behavior and cleanup failures, plus the scene consumer. The current scene fixture verifies all five authored boxes at a 0.1 CSS-pixel tolerance, actual Card slots, accessible controls, source-update/undo/reset behavior, Primary tokens, shadow-base overrides, Disabled, invalid-feed preservation, offline requests and stop. Color assertions wait for the real package transition to settle rather than assuming a two-frame reply proves physical presentation. Nested native slots and real native geometry/style/input require their separate consumer before #88 can close.
