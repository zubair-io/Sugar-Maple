# Authored scene projection — work toward #88

The props-only experiment uses intrinsic package layout. Protocol 2 adds a bounded, read-only scene feed to the trusted Web Awesome consumer and the separately sandboxed SwiftUI helper. It is partial implementation toward #88; editor diagnostics, the final comparison, review/CI and main integration remain incomplete. The production-integration NO-GO and arbitrary-source restrictions still apply.

`projectLibraryScene(document, settledRootItem, sourceRevision)` uses the authoritative scene and its settled model layout, not rendered DOM semantics. It preserves resolved parent-relative boxes from free/stack/grid/fill/hug/percent layouts, nested rotation, parent IDs, Default/header/footer slot names, resolved solid styles, pinned variants, local semantic overrides and bound source tokens. The result includes the document/root identity and source revision. A source/layout mismatch, missing bound token, gradient, unsupported font/kind, altered mapping or unsupported size fails explicitly before a feed is sent. The experiment supports only the exact trusted Web Awesome 3.14.0 mapping and ordinary frame/text/button/input nodes; it never evaluates a manifest's modules.

The strict packet has no document commands, filesystem paths, module URLs or executable source. Limits remain 256 KB per packet, 100 visible nodes, a 1,600 × 2,000 viewport, bounded coordinates, strings and styles. The root is an unrotated frame; rotated external ancestors are rejected. Duplicate IDs, broken/cyclic order, children beneath controls, unknown slots, mismatched semantic props and privileged keys are rejected. The existing iframe session, monotonically increasing transport revision, supersession, opt-in trust, stop/cancellation and capability restrictions remain. Authored source revisions cannot move backwards within a document.

`WebPreview.renderScene(scene, reset)` sends the immutable projection to actual pinned `wa-card`, `wa-input` and `wa-button` controls. Their host geometry uses resolved scene boxes. Card slot wrappers remove intrinsic padding and use the authored border to avoid shifting children. Source Card paint is applied directly; actual Button Default/Primary package appearance remains distinct from semantic fallback paint, with explicit fill/color/radius overrides reaching the actual shadow base. Pinned brand token bindings reach the real Primary appearance. This is a declared supported projection, not a claim that package default glyphs, focus effects or colors equal Canvas paint.

Inputs keep ephemeral values and focus across unrelated source updates and undo. An authored initial-value change or explicit reset replaces that local value; changing documents or removing a node discards its ephemeral state. Narrow node-ID action/change events are accepted only for the current enabled control kind, session and rendered revision. Neither the scene nor these events provide an authoring dispatcher in the preview.

`NativePreview.renderScene(scene, reset)` sends the same immutable geometry to real system SwiftUI controls in the existing signed App Sandbox helper. Swift validates strict packet, graph, style and mapped-property fields independently before changing state. The build generates pinned component definitions and unsupported-style defaults from the editor's metadata; the feed never chooses Swift source, imports or paths. Supported Default/Disabled controls use native appearance; Primary and nondefault library-only appearance properties return explicit unsupported diagnostics. Native Input custom fill/radius/stroke/letter spacing and nondefault line-height or multiline content are also unsupported, rather than silently ignored. Generic fonts use the corresponding system SwiftUI design; package glyph, focus, text metrics and default paint parity are not claimed.

Native layout preserves authored outer boxes and slot-child positions, not the legacy helper's independent VStack spacing. Fractional layout uses integral SwiftUI frames followed by presentation transforms, compensating parent transforms for child geometry; it avoids SwiftUI's layout pixel rounding without relaxing the 0.1-point gate. Native rendered replies include actual SwiftUI geometry observations and a PNG at the display's backing scale. These are outer presentation bounds, not a claim that intrinsic native control chrome or glyphs equal the Canvas or web package. Explicit Button/frame solid paint, radius and stroke overrides are rendered. Named slots remain validated scene-child identities and positions; they are not an arbitrary native component API.

Run `bun tools/library-preview-acceptance.ts` after explicitly installing/checking the pinned consumer cache. The gate covers strict contracts/typecheck, legacy real-package behavior and cleanup failures, plus the scene consumer. The web fixture verifies all five authored boxes at a 0.1 CSS-pixel tolerance, actual Card slots, accessible controls, source-update/undo/reset behavior, Primary tokens, shadow-base overrides, Disabled, invalid-feed preservation, offline requests and stop. Color assertions wait for the real package transition to settle rather than assuming a two-frame reply proves physical presentation.

Run `bun tools/native-library-preview-acceptance.ts` for real compilation/rendering, direct malformed/unsupported helper packets, authored outer-box geometry, fractional parent frames, nested slots, local overrides, Default/Disabled and source undo/reset, plus the existing sandbox and resource/cancellation regression checks. Run `bun prototypes/library-preview/native/scene-human-test.ts --trust-native-fixture` separately for physical Button action and TextField keyboard input, retaining focus and ephemeral values through a source label update and undo, then restoring authored input on reset. Native events remain limited to enabled node-ID action/change at the current settled session/revision. Whole-product accessibility and arbitrary source execution remain unproven.
